## Section 2 — Knowledge check (12 questions, 1 point each)

### Q1. Lesson 1. What is the difference between the two AI agents your students will use?

- A. The conventional AI is faster; the AI Mentor is more accurate
- B. They are the same agent with two different names
- C. The conventional AI is for text; the AI Mentor is for images
- D. **The conventional AI generates the initial code; the AI Mentor guides with questions and never writes the complete code** ✅

> *Feedback:* Keeping the roles separate is what keeps the mentor trustworthy. If one agent both teaches and hands over finished code, the student stops believing the questions are genuine.

### Q2. Lesson 1. What kind of personalisation is safe for a student to request from the AI?

- A. Technical requirements such as framerate or a physics engine
- B. **Theme, title, character or visual context** ✅
- C. Anything at all — the AI handles the consequences
- D. Only the title of the game

> *Feedback:* Safe personalisation stays at the surface: theme, title, character, visual context. Technical requirements are where generations start failing.

### Q3. Lesson 1. What is the homework after Lesson 1?

- A. Write a new prompt and generate a second game
- B. Read the generated JavaScript line by line
- C. **Change one simple value in the code, and know how to revert it if the game stops working** ✅
- D. Publish the prototype to Kodland Sparks

> *Feedback:* One value, and the ability to undo it. Reverting a change confidently is the skill the rest of the module depends on.

### Q4. Lesson 2. After the prototype is split into three files, where does the character's speed parameter live?

- A. **script.js** ✅
- B. style.css
- C. index.html
- D. In a separate config file

> *Feedback:* index.html holds structure and links, style.css the design, script.js the movement and logic.

### Q5. Lesson 2. What must the standard AI NOT do when restructuring the project?

- A. Split the file into three parts
- B. **Change the appearance or the logic of the game, or add external dependencies** ✅
- C. Keep the original variable names
- D. Explain what it changed

> *Feedback:* The split is mechanical. If appearance or logic changed, the AI did more than it was asked and the student has lost the thread.

### Q6. Lesson 2. A student asks you which speed value is the correct one. What do you say?

- A. Give them the value the template was built with
- B. Tell them speed does not matter at this stage
- C. Tell them to ask the AI Mentor for the right number
- D. **Let them choose by experimentation, and ask them to explain how it changes the movement** ✅

> *Feedback:* There is no correct value. The cycle is predict → modify → check → conclude, and the conclusion is theirs.

### Q7. Lesson 3. The AI rewrites the whole file instead of swapping the character image. What do you do?

- A. **Compare the before/after versions, and use the backup route only after 2 genuine attempts and one diagnostic hint** ✅
- B. Go straight to the backup template
- C. Accept the rewrite and continue with the new code
- D. Have the student write the replacement by hand

> *Feedback:* An unwanted complete rewrite is the known risk of this lesson. Compare versions first — the backup route is not the first move.

### Q8. Lesson 3. What does a complete prompt contain?

- A. Objective and the code, nothing else
- B. A description of the desired result in as much detail as possible
- C. **Objective + enough context + permitted changes + restrictions + a request for an explanation** ✅
- D. The error message plus the whole project

> *Feedback:* The request for an explanation is the part students skip — and it is what turns a generation into something they can learn from.

### Q9. Lesson 3. A change breaks the game. What is the correct debugging move?

- A. Ask the AI to fix everything at once
- B. Restart the project from the backup template
- C. **Return to the last working version and find the first difference** ✅
- D. Undo every change made in the lesson

> *Feedback:* One testable hypothesis at a time. Fixing everything at once destroys the information you need.

### Q10. Lesson 4. Which AI is used in this lesson?

- A. **The AI Mentor exclusively** ✅
- B. Both, depending on what the student needs
- C. The conventional AI only
- D. Neither — this lesson is unplugged

> *Feedback:* The AI Mentor exclusively. The student formulates objective + current behaviour + a request for a hint; the Mentor never hands over the final code.

### Q11. Lesson 4. What is the character limit on each peer feedback field?

- A. 60 characters
- B. There is no limit
- C. 500 characters
- D. **180 characters** ✅

> *Feedback:* 180 characters for each of the three fields: overall impression, strong point, improvement. The limit is what forces the feedback to be specific.

### Q12. Lesson 4. A student has two half-finished mechanics with ten minutes left. What do you steer them towards?

- A. Finishing both quickly, even if they are unstable
- B. **One stable mechanic — it is preferable to two incomplete ones** ✅
- C. Publishing as is and fixing it as homework
- D. Reverting to the Lesson 3 version and skipping the mechanic

> *Feedback:* One stable mechanic beats two incomplete ones. And if the project was already unstable at the start of the class, go straight to the backup template.

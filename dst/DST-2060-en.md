## Section 2 — Knowledge check (12 questions, 1 point each)

### Q1. Lesson 1. What is the strict scope limit on the AI-generated character?

- A. Any number of characters, in any view
- B. It must include the background scenery
- C. **One single character, side view, transparent background** ✅
- D. It must be animated across at least two frames

> *Feedback:* One character, side view, transparent background — converted at 24×24 and named hero. AI is used once per lesson, always bounded.

### Q2. Lesson 1. Why should students not use "Sign in" in MakeCode during the initial test?

- A. **Account access is part of the homework, not of the first test** ✅
- B. The account is created automatically the first time they run the project
- C. Signing in disables the AI Helper
- D. Signing in resets the template to blank

> *Feedback:* Getting into the account is the homework. Keep the first run friction-free so the class reaches a working result.

### Q3. Lesson 1. Which of these belongs in Lesson 1?

- A. A visible score
- B. Game Over and WIN conditions
- C. New enemy types
- D. **Changing the rhythm interval from 1200 to 900 or 1500** ✅

> *Feedback:* Only the visual remix plus the rhythm change. Score, Game Over, WIN and new enemies belong to later lessons — adding them early breaks the build order.

### Q4. Lesson 2. A student's score keeps resetting to zero while they play. What is the most likely cause?

- A. The coin sprite has the wrong kind
- B. **The set score block is inside "on game update"** ✅
- C. The score variable was never created
- D. The rhythm interval is too fast

> *Feedback:* Score must be set to 0 at game start via Advanced → Info, never inside a loop like "on game update".

### Q5. Lesson 2. The collectible does not add +1 on contact. What do you check first?

- A. The background colour
- B. The AI prompt used to generate the coin
- C. The rhythm interval
- D. **That the kind in the create block and in the overlaps block match** ✅

> *Feedback:* A mismatched kind between create and overlaps is the classic cause. Always compare the two before looking anywhere else.

### Q6. Lesson 2. What exactly does the homework require the student to submit?

- A. The MakeCode Share link
- B. A screenshot of the running game
- C. **The Kodland Sparks link, obtained after Publish** ✅
- D. The exported .png of the coin sprite

> *Feedback:* The Sparks link after Publish — not just MakeCode's technical Share link. This is where their first beta actually lives.

### Q7. Lesson 3. Where must the LOSE block NOT be placed?

- A. In the on start block
- B. **Inside the coin-collection overlaps** ✅
- C. In the game update loop
- D. On the hero sprite

> *Feedback:* Never inside the coin-collection overlaps. Also check the defeat block correctly replaces the original reset.

### Q8. Lesson 3. How much real independent practice time should students get before you intervene?

- A. **About 17 minutes** ✅
- B. About 5 minutes
- C. About 2 minutes
- D. None — guide them continuously

> *Feedback:* Roughly 17 minutes. The productive struggle is the point of the lesson, not an accident in it.

### Q9. Lesson 3. Students choose a victory condition from three options, A, B or C. What is your role?

- A. **Let each student choose their own, and in the parade show the different forms without ranking them** ✅
- B. Recommend the option that produces the cleanest code
- C. Assign options so the group covers all three evenly
- D. Choose one option for the whole group to keep debugging simple

> *Feedback:* No imposing and no comparing. Showing three different valid victories is exactly what makes the parade worth doing.

### Q10. Lesson 4. What makes a prompt specific enough for the AI Helper?

- A. A short sentence describing the feeling the mechanic should create
- B. **One single mechanic, the game context, the complete JavaScript pasted, and clear restrictions** ✅
- C. A list of every mechanic the student wants, so the AI can pick
- D. A screenshot of the game plus the mechanic name

> *Feedback:* One mechanic at a time, with the complete JavaScript pasted rather than fragments. Vague prompts are the main cause of a broken project in this lesson.

### Q11. Lesson 4. How should the student republish their updated game?

- A. Publish project again on Sparks, creating a new card
- B. Send only the MakeCode Share link
- C. **Share with "Update existing share link" ticked, then My Projects → Edit → Project link** ✅
- D. Download the file and upload it manually

> *Feedback:* Publish project again creates an unwanted duplicate. Update the existing share link, then edit the existing Sparks card.

### Q12. Lesson 4. How should you close the module?

- A. Preview the next module in detail so students stay motivated
- B. Assign extra mechanics as holiday homework
- C. Review each student's code individually with the group watching
- D. **Celebrate the whole route — prototype → mechanic → launch — without previewing the next module's content** ✅

> *Feedback:* Close the whole arc with a group celebration. Detailed previews of the next module belong to the next module.
